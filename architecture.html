CDAO Target Data Architecture & Harness Context Layer
Hub-and-spoke consolidation into governed data products, with the harness shown as the reviewed context layer that helps Genie, SQL, and Python users interpret those products consistently.
Pre-decisional mapping. Any production AI, app, retrieval, or automation capability requires the appropriate USCIS/OIT governance, security, privacy, and approval path.
How to read this
The left side shows the move from today’s source-system pattern toward a governed hub-and-spoke model. The right side shows how governed products are consumed through Genie, SQL, Python, documentation, prompts, and future assistants.
What the harness adds
The harness is the reviewed context layer: definitions, caveats, approved counting logic, example questions, strong-answer examples, and review ownership. It improves interpretation; it does not replace platform governance.
What stays governed
Databricks, Unity Catalog, approved views, functions, policies, and data-owner controls remain the enforcement layer. Where logic must be technically enforced, it should be implemented in approved platform assets.
